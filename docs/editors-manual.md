# 編集者向けマニュアル(お知らせ更新ガイド)

対象: 非エンジニアの編集担当者。このマニュアルでは「お知らせ(news)を1件公開する」ための手順を説明します。

必要なもの: GitHubアカウント(事前に管理者からリポジトリへの追加を依頼されていること)。

## 1. ログイン

1. ブラウザで <https://www.bluemoon.works/admin/> を開く
2. 「GitHub」または「GitHubでログイン」(Login with GitHub)ボタンをクリック
3. GitHubの認証画面が開くので、自分のGitHubアカウントでログインして「Authorize」をクリック
4. 画面左側に「ニュース (News)」「イベント (Events)」「ページ (Pages)」のメニューが表示されたらログイン成功

## 2. お知らせを1件公開する

1. 左メニューの「ニュース」をクリック(お知らせの一覧が表示される)
2. 右上の「新規作成」(New entry)ボタンをクリック
3. 各項目を入力する:

   | 項目 | 入力内容 |
   |---|---|
   | タイトル (Title) | お知らせの見出し。例:「エントリー受付開始のお知らせ」 |
   | 日付 (Date) | カレンダーアイコンから公開日を選択(そのまま入力しても可) |
   | SNSリンク表示 (SNS links) | 通常は **オフのまま**。オンにすると本文の代わりにX(旧Twitter)とBlueskyへのリンクがトップページに表示される |
   | 本文 (Body) | お知らせの内容。改行や箇条書き(「- 」で始める)、リンクが使える |

4. 右下の「保存」(Save)ボタンをクリックし、続いて「公開」(Publish)ボタンをクリック
5. 公開は自動で処理され、**2〜3分後**にトップページ(<https://www.bluemoon.works/>)の「NewsLine」欄に新しいお知らせが表示される

> 公開後の処理(ブランチへのcommit・mainへのマージ・本番デプロイ)はすべて自動で行われます。編集担当者は「保存」→「公開」の操作だけで構いません。

## 3. お知らせの編集・削除

- **編集**: 「ニュース」一覧で対象のお知らせをクリック → 内容を修正 → 「保存」→「公開」
- **削除**: 一覧で対象の行のメニュー(「⋮」など)から削除(Delete)を選択

## 4. プレビュー

編集画面の「プレビュー」(Preview)をクリックすると、トップページが別ペインに表示されます。お知らせはトップページのNewsLineに載るため、どこに表示されるかの確認に使えます。

なお、執筆中の未公開の内容はプレビューに反映されません(保存・公開後のみ反映)。最終確認はトップページで行ってください。

## 5. 画像を本文に挿入する

本文エディタの画像ボタンから画像を選択すると、自動的にアップロードされて本文に挿入されます。アップロードされた画像は `/images/...` としてサイトに配信されます。

## 6. よくあるトラブル

| 症状 | 原因と対処 |
|---|---|
| GitHubのログイン画面に進めない | GitHubアカウントがリポジトリの collaborator に追加されていない可能性。管理者にGitHubユーザー名を伝えて追加を依頼する |
| 「保存」後に公開ボタンが押せない | 必須項目(タイトル)が未入力。タイトルを入力してから保存・公開する |
| 公開したのにトップページに表示されない | 自動ビルドがまだ完了していない(2〜3分待つ)。それでも表示されない場合は管理者に連絡 |
| 日付を入れ忘れた | 一覧の一番下(日付順の末尾)に表示される。日付を設定して保存・公開し直す |
| ログイン画面がおかしい/エラーが出る | ブラウザのキャッシュを更新して再試行。解決しない場合は管理者に連絡 |

## 7. 管理者向けメモ

- **編集者の追加**: GitHub リポジトリ `azumag/bluemoon` の Settings → Collaborators からGitHubユーザー名を追加する
- **公開の仕組み**: CMSの書き込み先は `cms-drafts` ブランチ。公開操作のcommitがあると `cms-publish.yml` が検証後にmainへ自動マージし、mainのデプロイCIが本番へ反映する。`cms-drafts` はルールセットでコンテンツパス(`src/content/**`・`src/assets/events/**`・`public/images/**`)のみ編集可能
- **自動マージの前提**: リポジトリのSecret `CMS_MERGE_PAT`(fine-grained PAT、リポジトリ限定・Contents read/write)が必要。未設定だと自動マージが失敗する
- **マージ競合時**: `cms-publish.yml` が失敗するので、手動でmainをcms-draftsへマージして解決する
- **CMSの構成変更**: `public/admin/config.yml`(リポジトリ内)を編集し、mainブランチへマージすると自動デプロイされる
- **初回セットアップ**: [README.md](https://github.com/azumag/bluemoon/blob/main/README.md) の「コンテンツ管理(Sveltia CMS)」セクションを参照
